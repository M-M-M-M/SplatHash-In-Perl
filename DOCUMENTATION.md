# SplatHash Perl Documentation

## Public API

### `encode_raw($rgba, $width, $height)`

Encodes a row-major RGBA byte string and returns a 16-byte SplatHash. Width and
height must be positive integers, and the input length must equal
`width * height * 4`. Alpha is ignored to match the Go RGBA fast path.

### `decode($hash)`

Decodes a 16-byte SplatHash and returns a row-major 32x32 RGBA byte string.
Every output pixel has alpha 255. Inputs of any other length are rejected.

### `encode_file($path)`

Loads an image through `Imager` and passes its RGBA pixels to `encode_raw`.

## Command Line

```sh
splathash --input image.jpg --output preview.png
```

The command writes the decoded 32x32 PNG preview to `--output` and prints the
hash as 32 lowercase hexadecimal characters on stdout. Use `-i` and `-o` as
short aliases.

## Benchmarks

```sh
perl -Ilib bench/compare-perl-go.pl
```

The benchmark compares Perl against the pinned Go reference on the same image
files. It reports three modes:

- `encode`: image already loaded, hash generation only
- `decode`: hash already available, preview reconstruction only
- `full`: load image file and encode it

Use `--assets PATH` to benchmark an existing directory of `.jpg`, `.jpeg`, or
`.png` files. The committed `assets/` directory is used by default.

Encode runs 10 iterations per image by default. Decode runs 1000 iterations
per image because it is much faster and requires more samples for a stable
measurement. Use `--encode-iterations` and `--decode-iterations` to change
these independently, or `--iterations` to override both. Every measured
operation receives one untimed warm-up. An additional untimed encode prepares
the hash used by the decode benchmark.

Use `--format markdown` to generate the README-compatible table and
`--include-full` to additionally benchmark image loading plus encoding.

## Performance Notes

The encoder reads only the 1024 source pixels required by 32x32 point sampling.
It does not unpack or traverse the full source image. `encode_file` requests
those sampled pixels from Imager in one batch.

The matching-pursuit search precomputes valid Gaussian neighbors and uses
separate baryon and lepton inner loops, removing repeated boundary and channel
branches while preserving floating-point accumulation order.

The decoder performs Oklab-to-sRGB conversion inline and packs the complete
RGBA output once. Decoded fixture checksums protect this optimization from
changing output pixels.

These changes substantially improve pure Perl performance, but the numerical
search remains loop-heavy. A future optional XS backend is the practical path
to performance close to Go; the pure Perl implementation should remain the
portable fallback.

The author-only benchmark smoke test runs with:

```sh
SPLATHASH_RUN_BENCH=1 SPLATHASH_ASSETS=assets prove -lr xt
```

Run the non-benchmark author checks, including licence validation, with:

```sh
prove -lr xt
```

## Algorithm Compatibility

The implementation follows SplatHash v4:

1. Point-sample the input to a 32x32 Oklab grid.
2. Quantize the mean color to 6-bit L, 5-bit a, and 5-bit b.
3. Find three full-color baryons and three luminance-only leptons using
   sequential matching pursuit and zero-padded Gaussian correlation.
4. Optimize splat weights using ridge regression with lambda 0.001.
5. Pack the mean and six splats MSB-first into 128 bits.

Look-up tables, quantization, sampling coordinates, and color coefficients
match the Go source because small numerical changes can alter the final hash.

## Compatibility Tests

`t/fixtures/splathash-vectors.json` records hashes generated by the Go
reference commit `038b4f7025ec044ed9f319371e0ec2ed863a6f45`.
The fixtures use generated raw RGBA data so tests are deterministic and do not
depend on image decoder differences or network access.
